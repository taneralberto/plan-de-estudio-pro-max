# 1.5 — Complejidad y Estructuras Cotidianas

> **Estado:** `DIAGNÓSTICO` · unidad 5 del ROADMAP.
>
> **Prerrequisito:** poder leer, ejecutar y modificar una función que procese una colección.
>
> **Cierre:** aplica el [diagnóstico antes de estudiar](../METODOLOGIA.md#diagnóstico-antes-de-estudiar): 30–60 minutos con documentación y estudia después solo el hueco observado.

## Propósito

Predecir cómo crecen tiempo y espacio y elegir una estructura por sus operaciones, no por costumbre.

## Modelo mínimo

### Costo y entradas

Antes de asignar Big O, define qué representa `n` y, si hay dos colecciones, `m`. Cuenta las operaciones dominantes y distingue tiempo de espacio auxiliar. Las constantes se omiten al describir crecimiento, aunque pueden importar con datos pequeños.

Debes reconocer O(1), O(log n), O(n), O(n log n) y O(n²). Un loop anidado es O(n²) solo cuando ambos límites crecen de forma independiente con `n`; si recorren colecciones distintas puede ser O(n·m), y si el loop interior tiene un límite fijo puede seguir siendo O(n).

### Promedio, amortizado y peor caso

En las implementaciones habituales, `Map` y `Set` ofrecen lookup o membership esperado promedio cercano a O(1), con operaciones de crecimiento amortizadas; no es una garantía universal por operación. Construir un `Map` o `Set` desde `n` elementos cuesta O(n) tiempo y O(n) espacio adicional. Explicita los supuestos y al menos un peor caso relevante.

### Elección cotidiana

- **Array:** conserva orden, facilita iteración y acceso por índice; buscar membership es O(n).
- **Map:** representa asociaciones clave→valor y evita búsquedas lineales repetidas. Los objetos usados como claves se comparan por identidad.
- **Set:** representa membership y unicidad en memoria; no reemplaza un constraint `UNIQUE` en la base de datos.
- **Queue:** expresa FIFO. Analiza la implementación real: en un Array de JavaScript, `shift()` desplaza elementos y no debe asumirse O(1).

Elige considerando accesos, escrituras, orden, unicidad, tamaño y costo de mantener la estructura.

### Medición como contraste

Usa un contador de operaciones y al menos dos escalas de datos para contrastar la predicción. El tiempo medido complementa el análisis, pero no demuestra por sí solo una clase de complejidad; registra entorno y ruido. El benchmark de un sistema completo pertenece a la unidad 13.

### JIT

Linked lists, heaps, árboles, grafos/BFS/DFS, implementaciones de hashing y colisiones, sorting propio, recursión y programación dinámica se abren cuando un problema real requiere esa estructura o algoritmo.

## Ejercicio único — reducir lookups repetidos

**Diagnóstico:** 30–60 minutos; si aparece un hueco, extiende la práctica hasta 90 minutos.

1. Elige una función real o sanitizada que cruce dos colecciones o repita `includes`/`find` dentro de un loop.
2. Antes de editar, define `n` y `m`, deriva tiempo y espacio, y predice qué ocurrirá al multiplicar los datos por 10.
3. Añade un contador de comparaciones y ejecuta dos tamaños reproducibles.
4. Si corresponde, construye una vez un `Set` o `Map`; recalcula el costo total, incluida su construcción y memoria. Si no corresponde, conserva el Array y justifica la decisión.
5. Compara contador y tiempos como evidencia complementaria; registra tamaños, entorno y ruido.
6. Documenta el límite: cuándo construir o mantener el índice hace preferible Array, o cuándo el requisito FIFO exige Queue.

Entrega un informe breve con función, predicción, mediciones, decisión y límite. Puede provenir de código propio o laboral sanitizado; no añade otra aplicación de proyecto.

## Done cuando

- [ ] El informe define todas las variables de entrada y justifica tiempo y espacio desde operaciones, no desde la forma visual de los loops.
- [ ] La predicción de crecimiento se contrastó con un contador de operaciones en al menos dos escalas.
- [ ] La elección entre Array, Map, Set y Queue se apoya en accesos, escrituras, orden, unicidad y tamaño reales.
- [ ] Si se introdujo Map o Set, se contabilizaron construcción y memoria; si no, se justificó conservar Array.
- [ ] Se documentó al menos un peor caso o supuesto y qué dato cambiaría la elección.
- [ ] Puede explicar problema, decisión, evidencia e incertidumbre consultando documentación.
