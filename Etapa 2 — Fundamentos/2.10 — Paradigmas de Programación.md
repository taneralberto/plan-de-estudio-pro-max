# 2.10 — Paradigmas de Programación

> **Estado histórico:** integrado; no es una unidad que debas completar por separado.

Los conceptos útiles se practican dentro de límites y cambios reales:

- pureza, inmutabilidad, composición, encapsulación, polimorfismo y contratos → [3.2 — Diseño Modular y Arquitectura Evolutiva](../Etapa%203%20—%20Arquitectura/3.2%20—%20Patrones%20de%20Arquitectura%20Avanzados.md);
- concurrencia, streams y efectos asíncronos de backend → [2.7 — Concurrency y Parallelism](2.7%20—%20Concurrency%20y%20Parallelism.md) y [2.11 — Sistemas Operativos](2.11%20—%20Sistemas%20Operativos%20(Profundizar).md);
- Observables y operadores RxJS → [3.5 — State Management](../Etapa%203%20—%20Arquitectura/3.5%20—%20State%20Management.md), en la ruta Web JIT.

No reescribas código imperativo como funcional ni extraigas interfaces solo para demostrar un paradigma. El criterio es si la decisión reduce estados, dependencias o costo de cambio observables.
