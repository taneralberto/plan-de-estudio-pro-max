# 3.4 — Cómo funciona el Browser

> **Estado: JIT** · Referencia Web no bloqueante.

## Cuándo abrir

Ante una interacción lenta, trabajo que bloquea la UI, una decisión de renderizado o una necesidad Web que quizá ya cubra una API nativa.

## Conceptos mínimos

- **Pipeline de renderizado:** HTML/CSS forman los árboles usados para style, layout, paint y composición; mide qué etapa domina antes de optimizar.
- **Main thread y workers:** el DOM vive en el hilo principal; mueve trabajo CPU-intensivo a un Worker solo después de medirlo y considera el coste de transferir datos.
- **CSR, SSR y SSG:** elige según contenido, SEO, latencia, frescura y coste operativo, no como regla global de la aplicación.
- **APIs nativas:** revisa primero `AbortController`, observers, `Intl`, Performance APIs y Web Workers antes de incorporar otra dependencia.

## Evidencia opcional

Un perfil de una carga o interacción real con el cuello identificado y una comparación antes/después de un cambio pequeño.
