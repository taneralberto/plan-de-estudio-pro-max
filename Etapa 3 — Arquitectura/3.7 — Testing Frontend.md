# 3.7 — Testing Frontend

> **Estado: JIT** · Especialización Web no bloqueante. Los fundamentos y criterios canónicos están en [`1.3 — Testing Fundamentals`](<../Etapa 1 — Entrada/1.3 — Testing Fundamentals.md>).

## Cuándo abrir

Cuando un riesgo específico de UI no quede cubierto por los tests de la unidad 3 o requiera comprobar comportamiento en un navegador real.

## Conceptos mínimos

- **Comportamiento observable:** consulta por rol, nombre o texto e interactúa como una persona usuaria; evita propiedades internas del componente.
- **Integración de UI:** cubre renderizado, eventos y estados de carga/error en el boundary mínimo que dé confianza.
- **Navegador real:** reserva un flujo crítico para comprobar navegación, foco, red y APIs que una simulación DOM no reproduce bien.
- **Regresión visual:** úsala solo para UI compartida y estable, con revisión explícita de cambios intencionales.

## Evidencia opcional

Un test enfocado en un riesgo real de UI o una traza/captura de un flujo crítico en navegador; no crea un requisito adicional de ruta.
