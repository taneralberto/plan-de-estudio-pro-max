# 4.11 — Orquestación de Containers y GitOps

> **Estado: JIT** · Referencia de plataforma no bloqueante.

## Cuándo abrir

Solo cuando Cloud Run u otra PaaS no cubra un requisito concreto de scheduling, aislamiento, escala o control operativo, o cuando un contexto laboral ya use Kubernetes.

## Conceptos mínimos

- **PaaS primero:** compara el requisito con Cloud Run antes de asumir el coste de operar un cluster.
- **Primitivas de Kubernetes:** entiende Pod, Deployment y Service como unidad de ejecución, reconciliación y red estable.
- **Salud y capacidad:** configura probes, requests y limits según el comportamiento medido; diagnostica eventos y estado antes de reiniciar a ciegas.
- **GitOps después:** evalúa reconciliación desde Git solo cuando exista un cluster real y un problema operativo que la justifique.

## Evidencia opcional

Una nota de decisión PaaS vs Kubernetes o el diagnóstico documentado de un workload existente; no hace falta crear un cluster.
