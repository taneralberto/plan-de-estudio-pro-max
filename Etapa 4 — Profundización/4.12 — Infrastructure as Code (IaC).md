# 4.12 — Infrastructure as Code (IaC)

> **Estado: JIT** · Referencia de plataforma en GCP no bloqueante.

## Cuándo abrir

Cuando la infraestructura de GCP deba ser repetible, revisable o recuperable y los cambios manuales ya no ofrezcan trazabilidad suficiente.

## Conceptos mínimos

- **`plan` y `apply`:** revisa el cambio propuesto antes de modificar recursos y conserva el plan como límite entre intención y ejecución.
- **State remoto y locking:** almacena el state de GCP en un backend GCS protegido y con bloqueo para evitar escrituras concurrentes; trata el state como dato sensible.
- **Drift:** compara configuración, state e infraestructura real antes de corregir una desviación.
- **Secretos:** no los incrustes en HCL ni en outputs; usa referencias y el gestor de secretos adecuado.
- **Ansible solo ante hosts reales:** incorpóralo si hay máquinas que configurar; Cloud Run y otros servicios gestionados pueden eliminar esa necesidad.

## Evidencia opcional

Un `terraform plan` pequeño, sin secretos, revisado junto con la configuración del backend. No requiere aplicar ni destruir infraestructura.
