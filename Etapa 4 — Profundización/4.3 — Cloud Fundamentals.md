# 4.3 — Entrega Práctica en GCP

> **Estado:** `ACTIVO ★` · Cierre de la unidad 16 del [ROADMAP](../ROADMAP.md).
> **Prerrequisitos:** imagen de [4.1](4.1%20—%20Containerización%20Avanzada.md) y pipeline diseñado en [4.2](4.2%20—%20CI-CD%20(Integración%20y%20Entrega%20Continua).md).
> **Cierre:** cumple el [cierre de una unidad crítica](../METODOLOGIA.md#cierre-de-una-unidad-crítica).

## Propósito

Desplegar un backend pequeño en GCP, saber qué identidades y servicios participan, verificarlo y recuperarlo. No estudiar catálogos de cloud ni replicar infraestructura que un servicio gestionado ya resuelve.

## Modelo mínimo de GCP

| Necesidad | Servicio de esta unidad |
|---|---|
| ejecutar container HTTP | Cloud Run service/revision |
| guardar imagen | Artifact Registry |
| PostgreSQL gestionado | Cloud SQL |
| identidad de CI/runtime | IAM service accounts + Workload Identity Federation |
| secretos | Secret Manager |
| logs básicos | Cloud Logging |

Un proyecto GCP delimita billing, IAM y recursos; región afecta latencia, disponibilidad, residencia y coste. Elige una región cercana y compatible con Cloud Run/Cloud SQL. VPC, load balancer, CDN, Cloud Storage y múltiples regiones quedan fuera si el servicio no los necesita.

### Cloud Run no es un servidor tradicional

- Las instancias pueden iniciar/detenerse y escalar horizontalmente.
- El filesystem local es efímero; estado durable va a servicios externos.
- Concurrency, CPU/memory, min/max instances y timeout son límites configurables.
- Cold start y scale-to-zero son trade-offs medibles, no defectos universales.
- La aplicación debe escuchar `PORT`, manejar `SIGTERM` y tolerar varias instancias.

### Managed vs self-hosted

Compara coste financiero, tiempo operativo, backups/restore, actualizaciones, observabilidad, compliance, lock-in y experiencia del equipo. Para este laboratorio usa Cloud Run y Cloud SQL: la decisión enseña el camino gestionado, no declara que sea siempre mejor.

### IAM como grafo de acceso

Pregunta: **qué identidad necesita qué acción sobre qué recurso y durante cuánto tiempo**.

- GitHub obtiene credencial efímera para publicar/desplegar.
- Cloud Run usa otra service account para leer solo sus secretos y conectar a su base.
- Invocación autenticada es el default del laboratorio.
- No uses roles Owner/Editor ni descargues claves permanentes para simplificar.

## Ejercicio único — Deploy reproducible y rollback

Aplica esta unidad a `safe-change-api` o un backend equivalente ya probado. Usa un proyecto sandbox sin usuarios ni datos reales y activa alertas/presupuesto antes de crear recursos.

1. Registra región, recursos, costo esperado y comando de teardown.
2. Crea Artifact Registry, Cloud Run, Cloud SQL PostgreSQL y Secret Manager con identidades separadas para CI/runtime.
3. Configura conexión a Cloud SQL y secretos sin incluir credenciales en imagen, repo o logs.
4. Configura GitHub Actions: checks → build una vez → push por SHA → deploy del digest → smoke test autenticado.
5. Guarda commit, image digest, revisión de Cloud Run y salida del smoke test.
6. Despliega una segunda revisión inocua; dirige tráfico a ella y vuelve a la anterior sin rebuild.
7. Verifica que un principal no autorizado no puede invocar el servicio ni leer el secreto.
8. Elimina recursos al terminar o documenta por qué permanecen y cuánto cuestan.

No añadas frontend, bucket, CDN, funciones, Kubernetes ni IaC. La unidad 17 agregará telemetría e incidente; aquí bastan logs de plataforma y smoke test.

## Done cuando

- [ ] Un push autorizado produce un artifact por SHA/digest y despliega exactamente ese artifact.
- [ ] El servicio usa Cloud SQL/Secret Manager sin credenciales persistentes en repo, imagen o CI.
- [ ] CI y runtime tienen identidades distintas y permisos mínimos justificables.
- [ ] El smoke test funciona con identidad válida y el acceso no autorizado falla.
- [ ] Puedes relacionar commit, digest, revisión y logs de entrega.
- [ ] Demostraste rollback a una revisión anterior sin reconstruir la imagen.
- [ ] Registraste coste y teardown, y no dejaste recursos accidentales.
- [ ] Cumpliste artefacto, caso negativo y la recuperación del cierre crítico.
