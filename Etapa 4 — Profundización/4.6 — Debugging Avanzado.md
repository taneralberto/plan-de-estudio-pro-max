# 4.6 — Debugging Avanzado

> **Estado histórico:** integrado; no es una unidad que debas completar por separado.

El contenido se distribuye según la clase de fallo:

- método hipótesis→evidencia, debugger de Node.js, call stack y test de regresión → [1.1 — Debugging y Evidencia](../Etapa%201%20—%20Entrada/1.1%20—%20Debugging%20Básico.md);
- heap snapshots, memory leaks, streams y backpressure → [2.11 — Sistemas Operativos](../Etapa%202%20—%20Fundamentos/2.11%20—%20Sistemas%20Operativos%20(Profundizar).md);
- procesos y señales → [2.9 — Linux y Shell](../Etapa%202%20—%20Fundamentos/2.9%20—%20Linux%20y%20Shell%20Productivo.md); `strace` queda JIT para comprobar una hipótesis concreta sobre una syscall bloqueada o fallida, contrastando la salida con `man strace`;
- `tcpdump`, DNS, TLS y tráfico de red → [2.12 — Redes](../Etapa%202%20—%20Fundamentos/2.12%20—%20Redes%20en%20Profundidad.md);
- code archaeology y debugging en código desconocido → [4.7 — Leer Código Ajeno y Code Review](4.7%20—%20Leer%20Código%20Ajeno%20y%20Code%20Review.md).

Usa esas herramientas cuando la evidencia indique memoria, kernel, red o contexto desconocido. Chrome Performance y debugging específico del browser quedan en la ruta Web JIT. No hagas una ronda de ejercicios por herramienta.
