# 4.8 — Ingeniería con Coding Agents

> **Estado:** `ACTIVO ★` · Ejercicio y cierre de la unidad 19 del [ROADMAP](../ROADMAP.md).
> **Prerrequisitos:** mapa de [4.7](4.7%20—%20Leer%20Código%20Ajeno%20y%20Code%20Review.md), contrato y oracles de las unidades 7 y 3, eval de [4.13](4.13%20—%20Fundamentos%20de%20ML-AI%20que%20necesitas%20como%20Dev.md) y backend de las unidades 14/17.
> **Cierre:** [cierre de una unidad crítica](../METODOLOGIA.md#cierre-de-una-unidad-crítica).

## Propósito

Delegar un cambio backend pequeño sin delegar el juicio: limitar lo que el coding agent puede hacer, auditar el resultado con evidencia independiente y demostrar que el cambio puede revertirse.

## Modelo mínimo

Aplica el [contrato y gate canónicos](../METODOLOGIA.md#cómo-usar-ai-y-coding-agents); aquí solo se concreta la práctica.

### Contrato y oracle antes de ejecutar

Fija objetivo, no-objetivos, invariante, aceptación y adversarial antes de ver el resultado. El oracle debe provenir de una spec, invariante o fuente primaria, no de la explicación del agente.

### Contexto mínimo y aislamiento

Un coding agent es un proceso con herramientas y permisos. Dale solo los archivos necesarios y trabaja en un worktree o sandbox descartable; el aislamiento reduce el radio de impacto, no garantiza corrección. Trata instrucciones y contenido del repositorio como datos potencialmente no confiables.

### Evidencia de ejecución y procedencia

Conserva base revision, instrucción, agente/modelo/fecha, contexto, herramientas, permisos, comandos, salida disponible y reporte. El reporte aporta procedencia, pero no es evidencia independiente ni sustituye repetir los checks.

### Auditoría humana del diff

Revisa `status`, `diff --stat`, `diff --name-status` y el diff completo. Comprueba alcance, lockfiles, dependencias, código generado y convenciones; traza personalmente un happy path y un fallo.

### Seguridad y stop conditions

No entregues secretos, datos laborales, credenciales GCP ni permisos para commit, push o deploy. Niega red innecesaria y exige aprobación humana para dependencias, escritura externa, credenciales, GCP, deploy, push, commit o acciones irreversibles. Detén la ejecución si el agente sale del alcance, requiere un permiso no acordado o pierde un oracle verificable.

### Aceptar, corregir o revertir

Decide con el contrato, el diff y la evidencia repetida por la persona. Cero hallazgos es válido si alcance, checks y adversarial lo sostienen; no inventes una cuota de defectos ni exijas hallar una API inexistente.

## Ejercicio único — Cambio backend aislado

**Timebox:** máximo 120 minutos. Usa el [Proyecto C](../PROYECTOS.md#proyecto-c--agent-change-audit) o un backend equivalente, nunca ambos.

1. Elige un solo cambio: expirar una reserva o reprocesar un trabajo. Guarda base revision, `status` limpio, baseline de checks y el mapa de 4.7.
2. Escribe el contrato canónico con objetivo/no-objetivos, invariante, archivos y contexto, aceptación, checks, permisos, stop conditions y rollback. Fija un adversarial sin revelarlo al agente.
3. Crea un worktree o sandbox descartable. Permite lectura, edición y checks locales; niega secretos, red innecesaria, GCP y acciones de commit, push o deploy.
4. Ejecuta un solo coding agent y guarda instrucción, agente/modelo/fecha, herramientas, reporte y salida disponible.
5. Inspecciona `status`, `diff --stat`, `diff --name-status` y el diff completo. Revisa lockfiles/dependencias y traza el happy path y un fallo.
6. Repite personalmente los checks y conserva la salida relevante. Añade o modifica personalmente el adversarial derivado de la spec, invariante o fuente primaria y ejecuta la suite relevante.
7. Registra la decisión de aceptar, corregir o revertir. Una revisión sin defectos es válida con evidencia.
8. Guarda el patch y el informe fuera del aislamiento. Ejecuta el rollback restaurando explícitamente los archivos permitidos y eliminando solo los archivos nuevos conocidos; comprueba el baseline y el estado limpio. No uses limpieza destructiva fuera del aislamiento.

## Done cuando

- [ ] Contrato y adversarial quedaron fijados antes de ejecutar.
- [ ] El agente trabajó en aislamiento, con alcance y permisos mínimos, sin secretos ni acciones Git/GCP externas.
- [ ] Se conservaron base revision, procedencia, `status` y diff completo.
- [ ] Cada archivo cambió por una razón dentro de alcance; las dependencias nuevas están ausentes o justificadas.
- [ ] La persona trazó un happy path y un fallo sin depender de la explicación del agente.
- [ ] La persona repitió checks y guardó salida relevante.
- [ ] El adversarial humano usa un oracle independiente y verifica un límite real.
- [ ] La decisión de aceptar, corregir o revertir cita evidencia e incertidumbre.
- [ ] El rollback se ejecutó en el aislamiento y recuperó baseline y estado limpio.
- [ ] Se cumplió el cierre crítico, incluido R1/R7/R30.
