# 4.8 — Ingeniería con Coding Agents

> **Estado:** `ACTIVO ★` · Ejercicio y cierre de la unidad 18 del [ROADMAP](../ROADMAP.md).
> **Prerrequisitos:** mapa de [4.7](4.7%20—%20Leer%20Código%20Ajeno%20y%20Code%20Review.md), preparación de [1.6](../Etapa%201%20—%20Entrada/1.6%20—%20AI%20Literacy.md), contrato y oracles de las unidades 6 y 3, y backend de las unidades 13/16.
> **Cierre:** [cierre de una unidad crítica](../METODOLOGIA.md#cierre-de-una-unidad-crítica).

## Propósito

Delegar un cambio backend pequeño sin delegar el juicio: limitar lo que el coding agent puede hacer, auditar el resultado con evidencia independiente y demostrar que el cambio puede revertirse.

## Protocolo

Aplica el [contrato y gate canónicos](../METODOLOGIA.md#cómo-usar-ai-y-coding-agents); aquí solo se concreta la práctica. La preparación de [1.6](../Etapa%201%20—%20Entrada/1.6%20—%20AI%20Literacy.md) aporta el modelo de contexto, oracle, permisos y autonomía.

## Ejercicio único — Cambio backend aislado

**Timebox:** máximo 120 minutos. Usa el backend del [Proyecto A o B](../PROYECTOS.md) o un equivalente, nunca más de uno.

1. Elige un solo cambio: expirar una reserva o reprocesar un trabajo. Guarda base revision, `status` limpio, baseline de checks y el mapa de 4.7.
2. Escribe el contrato canónico con objetivo/no-objetivos, invariante, archivos y contexto, aceptación, checks, permisos, stop conditions y rollback. Fija un adversarial sin revelarlo al agente.
3. Crea un worktree o sandbox descartable. Permite lectura, edición y checks locales; niega secretos, red innecesaria, GCP y acciones de commit, push o deploy.
4. Ejecuta un solo coding agent y guarda instrucción, agente/modelo/fecha, herramientas, reporte y salida disponible.
5. Inspecciona `status`, `diff --stat`, `diff --name-status` y el diff completo. Revisa lockfiles/dependencias y traza el happy path y un fallo.
6. Repite personalmente los checks y conserva la salida relevante. Añade o modifica personalmente el adversarial derivado de la spec, invariante o fuente primaria y ejecuta la suite relevante.
7. Registra la decisión de aceptar, corregir o revertir. Una revisión sin defectos es válida con evidencia.
8. Guarda el patch y el informe fuera del aislamiento. Ejecuta el rollback restaurando explícitamente los archivos permitidos y eliminando solo los archivos nuevos conocidos; comprueba el baseline y el estado limpio. No uses limpieza destructiva fuera del aislamiento.

Esta entrega es también la eval mínima de una limitación observable del agente: contrasta su afirmación con el adversarial y los checks. No ejecutes otra eval por defecto.

## Informe mínimo

```md
Base revision / estado inicial:
Contrato y no-objetivos:
Contexto, herramientas, permisos y stop conditions:
Agente/modelo/fecha:
Archivos y resumen del diff:
Checks del agente / checks repetidos / salida:
Adversarial y origen del oracle:
Happy path / fallo:
Hallazgos por severidad o “sin hallazgos”:
Decisión y evidencia:
Rollback ejecutado / verificación:
Incertidumbre y riesgo residual:
```

## Done cuando

- [ ] Contrato y adversarial quedaron fijados antes de ejecutar; el agente trabajó en aislamiento con permisos mínimos, sin secretos ni acciones Git/GCP externas.
- [ ] Conservaste base revision, procedencia, `status` y diff completo; cada archivo y dependencia queda dentro del alcance o justificado.
- [ ] La persona trazó happy path y fallo, repitió los checks y añadió un adversarial con oracle independiente, sin depender de la explicación del agente.
- [ ] La decisión de aceptar, corregir o revertir cita evidencia e incertidumbre; el rollback recuperó baseline y estado limpio.
- [ ] Se cumplió el cierre crítico, incluida su recuperación.
