# 4.8 — Ingeniería con Coding Agents

> **Estado:** `ACTIVO ★` · Ejercicio y cierre de la unidad 18 del [ROADMAP](../ROADMAP.md).
> **Prerrequisitos:** mapa de [4.7](4.7%20—%20Leer%20Código%20Ajeno%20y%20Code%20Review.md); contexto/permisos de [1.6](../Etapa%201%20—%20Entrada/1.6%20—%20AI%20Literacy.md); oracles de la [unidad 3](../Etapa%201%20—%20Entrada/1.3%20—%20Testing%20Fundamentals.md); contrato y decisiones de la [unidad 6](../Etapa%201%20—%20Entrada/1.7%20—%20Documentación%20Técnica%20Profesional.md); contrato backend de la [unidad 13](../Etapa%203%20—%20Arquitectura/3.1%20—%20API%20Design.md) y backend desplegado de la [unidad 16](4.3%20—%20Cloud%20Fundamentals.md).
> **Cierre:** [cierre de una unidad crítica](../METODOLOGIA.md#cierre-de-una-unidad-crítica).

## Propósito

Delegar un cambio backend pequeño sin delegar el juicio: limitar lo que el coding agent puede hacer, auditar el resultado con evidencia independiente y demostrar que el cambio puede revertirse.

## Orientación

**Qué debes lograr:** delegar un cambio acotado, auditarlo sin confiar en el reporte y recuperar el estado inicial.
**Cómo abordarlo:** fija contrato y adversarial, ejecuta un agente aislado, revisa el diff, repite checks y demuestra rollback.
**Entregarás:** patch e informe mínimo con procedencia, evidencia independiente, decisión, incertidumbre y recuperación.
**Investiga fuera solo si:** una necesidad concreta activa los temas JIT; no compares modelos ni añadas otra eval por defecto.

## Protocolo

Aplica el [contrato y gate canónicos](../METODOLOGIA.md#cómo-usar-ai-y-coding-agents); aquí solo se concreta la práctica. La preparación de [1.6](../Etapa%201%20—%20Entrada/1.6%20—%20AI%20Literacy.md) aporta el modelo de contexto, oracle, permisos y autonomía.

## Ejercicio único — Cambio backend aislado

**Timebox:** máximo 120 minutos. Usa el backend del [Proyecto A o B](../PROYECTOS.md) o un equivalente, nunca más de uno.

**Contexto proporcionado:** un backend verificable, su spec/oracles, el mapa guardado en 4.7 y un worktree o sandbox descartable. Secretos, red innecesaria, GCP y acciones de commit, push o deploy están fuera de los permisos.

**Decisiones que debes tomar:** cambio único; objetivo/no-objetivos e invariante; archivos permitidos; aceptación y adversarial; herramientas, límites y stop conditions; decisión final de aceptar, corregir o revertir.

1. Elige un solo cambio: expirar una reserva o reprocesar un trabajo. Guarda base revision, `status` limpio, baseline de checks y el mapa de 4.7.
2. Escribe el contrato canónico con objetivo/no-objetivos, invariante, archivos y contexto, aceptación, checks, permisos, stop conditions y rollback. Fija un adversarial sin revelarlo al agente.
3. Crea el aislamiento. Permite lectura, edición y checks locales; niega secretos, red innecesaria, GCP y acciones de commit, push o deploy.
4. Ejecuta un solo coding agent y guarda instrucción, agente/modelo/fecha, herramientas, reporte y salida disponible.
5. Inspecciona `status`, `diff --stat`, `diff --name-status` y el diff completo. Revisa lockfiles/dependencias y traza el happy path y un fallo.
6. Repite personalmente los checks y conserva la salida relevante. Añade o modifica personalmente el adversarial derivado de la spec, invariante o fuente primaria y ejecuta la suite relevante.
7. Registra la decisión de aceptar, corregir o revertir. Una revisión sin defectos es válida con evidencia.
8. Guarda el patch y el informe fuera del aislamiento. Ejecuta el rollback restaurando explícitamente los archivos permitidos y eliminando solo los archivos nuevos conocidos; comprueba el baseline y el estado limpio. No uses limpieza destructiva fuera del aislamiento.

Esta entrega es también la eval mínima de una limitación observable del agente: contrasta su afirmación con el adversarial y los checks. No ejecutes otra eval por defecto.

## Entregable y evidencia — Informe mínimo

- **Artefacto:** patch e informe conservados fuera del aislamiento.
- **Evidencia independiente:** diff completo, checks repetidos personalmente y adversarial con oracle externo.
- **Caso negativo:** adversarial fijado antes de ejecutar y añadido o modificado personalmente después de recibir el cambio.
- **Límite o riesgo:** incertidumbre, riesgo residual, permisos/stop conditions y rollback comprobado.


## Done cuando

- [ ] El contrato quedó fijado antes de ejecutar el agente.
- [ ] El adversarial quedó fijado sin revelarlo al agente.
- [ ] El agente trabajó en un worktree o sandbox descartable con permisos mínimos.
- [ ] El agente no recibió secretos, red innecesaria ni permisos para acciones Git/GCP externas.
- [ ] Conservaste base revision, estado inicial y procedencia del agente.
- [ ] Conservaste `status`, `diff --stat`, `diff --name-status` y el diff completo.
- [ ] Cada archivo y dependencia cambiados está dentro del alcance o tiene justificación registrada.
- [ ] Trazaste personalmente el happy path.
- [ ] Trazaste personalmente un fallo.
- [ ] Repetiste personalmente los checks y conservaste la salida relevante.
- [ ] Añadiste o modificaste personalmente el adversarial con un oracle independiente.
- [ ] La decisión de aceptar, corregir o revertir cita evidencia.
- [ ] El patch y el informe quedaron guardados fuera del aislamiento.
- [ ] El rollback recuperó el baseline.
- [ ] El rollback dejó limpio el aislamiento.
- [ ] Explicaste problema, decisión, evidencia e incertidumbre.
- [ ] Completaste la recuperación R1 del cierre crítico.
